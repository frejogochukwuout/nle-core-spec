## §2 The spec's current color law (08/04 extraction)

### spec 08 (`08-color-grading.md`) — the grade model

- **§4.2 (L134-254): the wheels shader IS the spec** — a complete ported WGSL `colorWheelsFragment` operating on scene-linear 16-bit input: the 28-f32/112-byte uniform (:140-147, layout byte-identical to FreeCut), BT.709 luma + **0.18 linear mid-gray** masks (key changes #1-#3), the full 14-step op order, **no output clamp — HDR preserved** (key change #4, :242, :251). §17.A-port (L1281) carries the same shader in the quotes appendix.
- **§5 (L281-401): curves** — FreeCut model: 4 channels (master/red/green/blue), ≤16 points, **composition `out = channel(master(x))` — "the master curve is applied first, then per-channel"** (:299-300; bake at :330-332 `evaluateMonotoneCurve(redPoints, master)`); our overrides: **LUT width 256→1024, storage Uint8Array→Uint16Array** (:303-309, :339-365); §5.3 the shader samples a 1D LUT texture via `textureSample` (:377-392) — with the note that FreeCut bakes the width literal into the shader source (:395).
- **§7 (L441-536): 3D LUT** — `.cube` parser 8→16-bit (rgba16uint, :468-478), texture `rgba8unorm`→`rgba16float` + `writeTexture` upload (:494-510), **the sRGB bug** (FreeCut samples the LUT on linear values; we must convert linear→sRGB→lookup→linear, :512-534).
- **§8 (L540-575): qualifier** — 16-f32 uniform, param defaults (hueCenter 0°, hueWidth 35°, softness 20°/0.1); the ported shader converts **linear→sRGB before the HSV/luma computation** (§8.2 :567; §17.E-port :1595).
- **§9 (L579-626): power window** — FreeCut truth: **ellipse + rectangle ONLY** (no polygon, §16.E), inline single-pass mask (no mask texture, §9.2 :602), mask × strength → corrections; **"we add a grading node abstraction that composes qualifier ∩ powerWindow → grade as a chain… as a v2 feature"** (:624). No tracking anywhere.
- **§11 + §18 (L748-812, L1941-2100): scopes** — FreeCut's architecture = **compute shaders with atomicAdd accumulators + a separate render pass** (histogram compute :14-55 / render :57-179; vectorscope skin line 123°, 6 targets at 103/61/−13/−77/−119/167 on the 75% ring, §11.3 :777-790); our 10fps throttle is an addition (§11.4 :794). §18 = the full three-part bit-depth port: source texture `rgba8unorm`→`rgba16float`, **`linear_to_srgb` before binning** ("colorists expect gamma-encoded readings", §18.2 :1988-1996), histogram 256→1024 bins (×1023), waveform/vectorscope accumulator weights 256→65535, `setTransfer`/`setBitDepth` selectors (§18.2 Part 3 :2059-2071), upload via `uploadFromTexture(rgba16float)` — no canvas round-trip (§18.3 :2083); §18.4: the scope CANVAS stays 8-bit — "the scope is a visualization tool, not a precision output".
- **§12 (L816-861): real-time strategy** — (1) don't re-render the whole frame, only the grade pass; (2) **cache the linear-light working texture**; (3) coalesce slider events into one grade update per frame; the `linearCache: Map<mediaId, GPUTexture>` + `gradeDirty` sketch (:830-860).
- **§0 (L12-28): the R24 posture** — the mock = design reference ("the W4 math is r3's parity reference", 167 tests, :15); **the engine's instruments are ZERO code while the wire ADVERTISES `gpu-secondary-qualifier`/`gpu-power-window`** (the advertised-on-wire ≠ implemented trap, :18, :23); the engine's color ops are still FreeCut-baseline 8-bit `rgba8unorm` (46 sites/10 files, :18); **the r3 grade-math binding + parity (acceptance: max delta ≤ 1 LSB-equivalent, :22)**; the timeline-vs-clip sequential law REGISTERED as a pointer only — "the spec-side ruling is the C50 follow-up" (:25); "at r3 [the scopes] must plot ENGINE data (the mock is the reference PLOTTING implementation, not the data source)" (:17).

### §3.1 The composite answer to "to what extent can we reproduce these in WebGPU?"

**Every per-pixel surface the mock copied from Resolve is reproducible in WebGPU — and 5 of 7 are already specced AS WebGPU shaders** (wheels 08 §4.2/§17.A-port; curves 08 §5.3; LUT 08 §7.3-7.4/§17.D; qualifier 08 §8.2/§17.E-port; window 08 §9/§17.G-port; scopes 08 §11+§18 as compute). The two that are NOT GPU problems at all are the node graph's data model and the stills gallery (CPU state + multi-pass composition). **The genuine engineering risks are not "can WebGPU do it" but:** (1) the engine binding is still 8-bit `rgba8unorm` end-to-end (08 §0); (2) the scopes' measured-signal + readback venue is unruled; (3) the curve composition order conflicts between mock and spec; (4) the A3 gesture law and the node-graph model are unspecced; (5) browser support is WebGPU-only with a 10-bit-canvas feature matrix (04 §16.4) — the 8-bit fallback degrades precision but not capability.

## §5 The recommended architecture paragraph (the one-paragraph law the spec should carry)

> **Color venue law (proposed 08 §0 D-row, cross-linked 04 §8):** All per-pixel color math — the wheels' 14-step grade, the curve-LUT hop, the 3D LUT, the qualifier, the power window, tone mapping — runs as **WebGPU fragment passes over the scene-linear `rgba16float` working texture**, inside spec 04 §4's "all grading math happens here" box, one pass per grade node, ping-ponged (04 §5.2), composed between composite and display transfer; the clip→timeline (and future node-graph) grades are **sequential full passes, never params merges**. Curve and 3D-LUT data paths are **CPU-baked at edit time** (1024-entry 1D / 33³ 3D, 16-bit) and uploaded as textures — never evaluated per pixel on the CPU. **Scopes are compute-shader reductions over the post-grade signal with `linear_to_srgb` before binning** (08 §18), rendered **on-GPU** (graticule + trace render pass; zero readback), throttled to 10fps (08 §11.4); readback of the small u32 accumulators is permitted ONLY as the canvas2d-drawing fallback. The **eyedropper's 3×3 seed** is the one mandatory CPU readback (a 3×3 `copyTextureToBuffer`). UI gesture state (trackball-accumulating drags per DESIGN-R25 A3, transient buffers, one undoable commit per gesture) is CPU-side and reaches the GPU **only through the 112-byte uniform write** per committed grade. The mock's `src/lib/color/` CPU implementation is the **parity oracle** (≤1 LSB-equivalent, shared fixtures, CI), not a production venue; there is no production CPU render path (WebGPU-only, master Decision 4).
