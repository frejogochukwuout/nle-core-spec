## 2. The attacks on D47

### 2.1 Ruling 1 — the gesture-native per-family law (singular-absolute vs plural-delta)

**Attack A — "slip is a drag-session whose commit could be absolute (`sourceStart+δ`)."** Dissolved. The gesture produces a delta; the clamp engine is delta-in/delta-out (the tightest-δ law, G-SLIP-6); forcing absolutes would synthesize per-member values the gesture never computed — the exact D6-2 ground (b) (`arch-design-s17.md:152-155`). Precise-authoring of `sourceStart` (an inspector field edit) is a DIFFERENT commit surface — `updateElements` patches (per-element absolutes) — which the law already assigns to the patch family. No gap.

**Attack B — "overwrite-edit is a source-edit op placed absolutely."** Dissolved. Overwrite is not a drag-session verb: it is a composite (split+delete+insert / delete+move+insert, D31.6) or a dedicated op, whose CONSTITUENTS are placement-family verbs committing absolutes — exactly the ruling's placement branch. Consistent.

**Attack C — "ripple-trim commits a delta but needs the ripple MODE — does the verb carry mode params?"** Dissolved: `TrimCommand.ripple: boolean` exists today (`15:485-491`), survives the D47 rewrite (research §5.1 keeps `ripple?`), and the leverage-map mode 2 resolves to the flag ("one verb, one delta"). The toolbar's ripple toggle is caller/tool state (16's `toggleRipple` UI extension), correctly NOT a wire param.

**Attack D — "REDO after intermediate edits: do delta-shaped verbs replay correctly against a mutated scene? (the undo/redo argument FOR absolutes)."** Dissolved — and this was the strongest available attack on ruling 1. OT's undo machinery is **snapshot-based** (`timeline-core.ts:175-293`: `redo(current)` returns the stored `after` scene; no op is ever re-applied), and spec 15 §14.1 (`:4929-4938`) defaults BOTH venues to snapshots, with the inverse-command exception list containing no delta-shaped verb. Delta-vs-absolute has **zero undo-correctness consequence** in either implementation. The residual delta-replay surface is the REPLAY LOG (§14.6) — but a replay re-applies its recorded sequence from its recorded start state, so deltas are deterministic there; the only real exposure is OLD replay files carrying the retired `retimeKeyframe` — which is the §2-law-5 deprecation path (`15:117`: "Old replay files can be loaded against newer engines (with deprecation warnings)"), not a param-form problem.

**Attack E (LANDS, P3) — the family table is incomplete.** The law's dichotomy (verb-level delta vs per-element absolutes) does not classify `split` — `{elements[], splitTimeTicks}` is a THIRD form: flat member refs + a verb-level SHARED ABSOLUTE hoisted (exactly the C-2 scalar-hoisting law, but C-1's table omits it; `delete` (refs-only) is likewise unlisted). Not a contradiction — but the W4 amendment should classify both rows in the family table so battery_r28's coherence class has a closed set to check.
