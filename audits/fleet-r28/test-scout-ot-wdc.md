**Cite:** `src/lib/timeline/testing/harness.ts:23-115`; `src/app/page.tsx:158-240`.

### P-OT-2 · The headless command API — JSON-in/JSON-out, never-throws, coded results
**Definition:** `HeadlessTimelineApi.apply(command): CommandResult` where `CommandResult = { ok, code?: INVALID_PARAMS|NOT_FOUND|CONFLICT|NOOP|TRACK_LOCKED|INTERNAL_ERROR, error?, data? }` — the API NEVER throws at JSON callers; internal exceptions map to `INTERNAL_ERROR` (`api.ts:565-577`). Commands are plain JSON `{ type: "timeline.insert" | "timeline.move" | … , params }` (31 wire verbs; full union `api.ts:70-212`). The wire verbs map onto the core's named op methods (`core.insertElements/moveElements/trimElements/splitElements/deleteElements/rippleDeleteElements/duplicateElements/updateElements`, `ops/timeline-core.ts:887-1405`) — TWO faces, one engine: the JSON wire for consumers/tests, the typed ops for the UI's gesture pipeline.
**For:** edit semantics WITHOUT the UI — every op law (placement, overlap, ripple, lock-gating, validation) is asserted through the same boundary any consumer crosses. Malformed refs return `{ok:false, code}` instead of throwing, so negative-path tests are first-class.
**Cite:** `src/lib/timeline/headless/api.ts:1-23` (header: "Testability without UI tax"), `:565-577`, `:214-228`.

### P-OT-3 · **THE M49C VERB-CENSUS GATE — the exact mechanism (full detail)**
**The claim it machine-checks:** "the COMPLETE ui" — every wire command type that is supposed to route through the local UI has actually been fired through the REAL UI at least once across the whole run. It is NOT a test that walks the API surface and NOT a CI counter — it is a **recorder-instrumented accumulation gate at the runner layer, compared against LIVE-read registries**. Four layers:

**Layer 0 — tsc lockstep (compile time, both directions).** `WIRE_COMMAND_TYPES` is a hand-maintained `as const` array of the 31 verb strings (`api.ts:243-275`) kept in BIDIRECTIONAL lockstep with the `TimelineCommand` union by two type-level asserts — `_WireTypesCoverUnion` (a new verb in the union that is missing from the array is a compile error naming it) and `_WireTypesHaveNoExtra` (a listed verb that left the union is a compile error naming it) (`api.ts:277-297`). The same trick guards the exception registry: every key of `WIRE_UI_EXCEPTIONS` must be a real verb (`_WireUiExceptionsAreRealVerbs`, `api.ts:337-352`) — a typo'd or retired exception fails `bun run typecheck` at the declaration site, not at gate time. Adding a verb therefore fails typecheck until listed; listing it fails the coverage gate until it is UI-routed or registered as an exception.

**Layer 1 — the dispatch recorder with ORIGIN ATTRIBUTION (runtime, in the engine seam).** Every `apply`/`applyBatch` — including batch members — records one `WireLogEntry { command, result, seq, origin }` into a bounded ring (cap 500, `wireLogDropped` honesty counter) and adds `command.type` to UNBOUNDED coverage Sets (`api.ts:410-534`). HA-4-2 (audit s16) is the load-bearing subtlety: **origin attribution** — `WireOrigin = "ui" | "test"`, default `"test"` (the CONSERVATIVE direction: nothing counts as UI coverage unless it entered through an explicitly-stamped UI seam, so a routing regression fails the gate LOUDLY instead of passing silently on harness dispatches). The UI's own dispatch path (`useWireDispatch`) stamps `origin:"ui"` (`hooks/use-wire-dispatch.ts:80-88`); the exposed TEST handle `__VIEW_TEST__.wireDispatch` stamps `origin:"test"` (`app/view/page.tsx:467-474`). Two sets: `wireCoverage` (all origins — bookkeeping) and `wireUiCoverage` (**origin "ui" ONLY — the gate's sole evidence**; `api.ts:426-434`). A log-only reset (`wireLogReset`) exists so length-precision tests can clear the ring WITHOUT erasing the accumulated coverage (`api.ts:473-481`).

**Layer 2 — the node-side accumulator across page reloads (runner layer).** Each real-mouse phase navigates a FRESH page (`freshPage` → goto `/view`), which re-mints the wire and RESETS the recorder — so the runner merges each phase's page-local `wireUiCoverage` into a node-side `Set` AFTER EVERY phase (`mergeWireCoverage`, `run-timeline-tests.mjs:59-79`). The "last page carries the verb" law: only a suite's LAST page state carries that suite's coverage, so the merge must run before the next suite's freshPage — and coverage-critical phases are ORDERED before the gate (M55R's double-click authoring must run before phase 23; M58R's carrier test fires all three batch verbs on ONE page; `run-timeline-tests.mjs:321-368`). A Load-swap re-mints the wire mid-page, so the page carries BOTH coverage sets forward across the swap (`view/page.tsx:434-448`).

**Layer 3 — the gate itself (phase 23, runner layer).** Both registries are read LIVE from the page — never a test-local copy — because a node `.mjs` cannot import the TS barrel: `__VIEW_TEST__.wireCommandTypes = [...WIRE_COMMAND_TYPES]` and `__VIEW_TEST__.wireUiExceptions = Object.keys(WIRE_UI_EXCEPTIONS)` (`view/page.tsx:483-494`; the test-local six-verb copy was DELETED in D-ARCH-3 so the gate and the UI read ONE module). Then (`run-timeline-tests.mjs:389-431`):
```
missingCoverage = wireCommandTypes.filter(t => !accumulated.has(t) && !exceptions.has(t))
staleExceptions = exceptions.filter(t => !wireCommandTypes.includes(t))
coveragePass    = missingCoverage.length === 0 && staleExceptions.length === 0
```
The result lands as milestone **M49C** (1 test, title carries the law: "every routed wire command type fired through the REAL UI, origin-attributed … only origin:'ui' dispatches count") in the report and gates the process exit code. **Live result at this pin: "fired 28 distinct command types through the REAL UI … 3 documented exceptions; no gaps"** (report JSON, M49C) — the 28/3 arithmetic (31 census = 28 routed + 3 exceptions: `timeline.selectElements` (view-state by architecture), `timeline.advancePlayhead` (rAF-local ticker), `timeline.trim` (UI commits through the updateElements patch seam)).

### P-OT-4 · The history-entry laws (batch atomicity + NOOP honesty)
**Definition:** edit semantics are pinned by HISTORY DEPTH arithmetic, not just end-state: a batch commit is exactly ONE entry (`assertEqual(core.historyDepth(), 1, …)`); a TRUE NOOP creates NO entry ("phantom history entry" is a named failure mode — `milestones-tround.ts:187-214`, `milestones-round2.ts:199-208`); `applyBatch` is atomic via `beginHistoryTransaction` + depth-anchored rollback (undo exactly the entries the batch created, eviction suspended so even >100-entry batches roll back fully, `clearRedo()` after) and rejects `timeline.undo/redo` inside batches (`api.ts:2549-2632`); a batch that commits-then-fails rolls back COMPLETELY and **redo stays available** (F1B-7, `milestones-fixwave.ts:184-192`). Zero-delta retime is BENIGN `ok:true, changed:false` with NO entry (`milestones-darch6.ts:508-513`). The insert family has ONE shared per-element validator so `timeline.insertBatch` validates every member through the SAME law (`api.ts:623-637`).
**For:** the undo/redo contract as an observable invariant — the strongest single lever OT has for edit-semantics rigor (ripple, move, trim, split, batch, keyframes all get depth-pinned).
**Cite:** `api.ts:2549-2632`; `milestones-darch6.ts:171-306` (insertBatch: ONE entry + minted-refs echo + contiguous placement; mixed kinds INVALID_PARAMS (F1A-3); intra-batch self-overlap CONFLICT whole-batch reject; empty INVALID_PARAMS; locked-track TRACK_LOCKED; per-member errors carry the verb prefix); `milestones-tround.ts:133-214`.
