### 3.1 nle-engine (`3989506`; timeline.ts identical to R24 pin)

**`src/lib/nle/timeline/timeline.ts:4702` `performInsertEdit(trackId, sourceId, insertAtFrame, sourceStart, sourceEnd, {linked})` → `:4719 _performInsertEditImpl`** — the FreeCut 3-point port (`freecut source-edit-actions.ts:233-294`, header `:4511-4531`). Deep-read verdict: **THE DAVINCI LAW IS IMPLEMENTED — in the unlinked path.**

- **3-point semantics `:4521-4527`**: point 1/2 = source in/out (`sourceStart`/`sourceEnd`, source frames); point 3 = `insertAtFrame` (timeline); implied duration = `sourceEnd − sourceStart`; **assumes sourceFps === timelineFps** (callers pre-convert). Validation: track-not-found/locked → throw (`:4729-4730`); `sourceRange <= 0` → throw (`:4737-4739`); `clipDuration = max(1, sourceRange)` (`:4740`).
- **Phase 1 — SPLIT `:4742-4774`**: finds the clip **strictly straddling** the insert frame on the target track (`c.from < insertFrame < c.from + duration`, `:4746-4751`) and splits it via `_splitClipPure` (`:4551-4671`): left half keeps `from` (stays in place), right half gets `from = insertFrame` (shifting in Phase 2 by construction) — **exactly the mock's mid-clip law**. `_splitClipPure` mirrors `splitClip`'s math: source-boundary split via `calculateSplitSourceBoundaries` (`:4582-4589`), **reversed-clip source swap** (`:4605-4619`), transition remap + linkedGroupId relink via `applySplitBookkeeping` (`:4643-4646`), and — **deliberately, `:4541-4544` — NO linked-companion fan-out** (single-track split).
- **Phase 2 — SHIFT `:4776-4802`**: every clip on the target track with `from >= insertFrame` shifts right by `clipDuration`; when `linked` (default **true**) the shift set expands through `findLinkedClips` (`:1460-1483` — whole-`linkedGroupId` filter, or legacy originId+sourceId+position match) to companions on other tracks ("preserving sync", `:4687-4690`). **No ripple flag exists — the push is intrinsic.** ✓ mode card.
- **Phase 3 — INSERT `:4804-4816`**: new clip at `insertFrame` with source range `[srcStart, srcEnd)`, **type derived from the track kind** (video→VideoClip / audio→AudioClip, `_buildSourceEditClip :5061-5116`).
- **Transitions `:4818-4822`**: dangling refs dropped defensively; the split's transition remap is in `_splitClipPure`. **R1-B4 abort law `:4763-4773`**: if the split point lands inside a transition's consumed window (`isInTransitionOverlap`, `:4567-4571`), `_splitClipPure` returns null and **the whole edit aborts empty** (`{insertedClipId:'', shiftedClipIds:[]}` — "refuse, no partial commit", the no-overlap invariant guarded). A DaVinci-silent constraint: the mock does not depict it.
- **Atomicity `:4698`, `:4710-4712`**: ONE `_commit`; `execute()` wrap = **one undo entry** (P1.14).
- **Tests**: `tests/vitest/engine/timeline-edit-ops.test.ts` — 4 pins: 2× the R1-B4 abort law, 1× mid-clip insert OUTSIDE the window (insert at 40 mid-c1: split proceeds, `hasOverlap(after)===false`, one history entry, `:99-112`), 1× fps pin. Browser milestone 7.6 `src/app/page.tsx:2497-2534`: boundary insert at c2's start, downstream c3 40→50, **`{linked:false}`**.

**⚠ LIVE-PROBED DEFECT (this audit, /tmp vitest run against the real class, engine tree clean):** with a **linked** straddler and default `linked:true`, the mid-clip insert **corrupts the layout**:
`performInsertEdit(V1, m, 150, 0, 50)` over video S `[100,300)` (group G) + audio A `[100,300)` (group G) + downstream D `[300,400)` yields V1 spans `[150,200) S-left`, `[150,200) NEW`, `[200,350) S-right`, `[350,450) D` — **the LEFT half is shifted into the inserted clip's span (exact overlap)**, and the audio companion shifts whole to `[150,350)` (unsplit → A/V desync at the insert region). Root cause chain: (1) `_splitClipPure` emits a **single-entry** `SplitResultEntry`, so `relinkSplitSegments` (`:668-690`) **preserves the original linkedGroupId on BOTH halves** (relink only fires when ≥2 linked clips split together, `:674-678`); (2) Phase 2's `findLinkedClips(rightHalf)` returns the whole group — **including the left half**; (3) the left half (from < insertFrame) is shifted +clipDuration like everything else. The unlinked baseline is exact (`[100,150)+[150,200)NEW+[200,350)+[350,450)`, overlap false). **Unpinned**: all 4 vitest pins + milestone 7.6 use `linked:false` or unlinked fixtures. Probe artifacts: `/tmp/r25-insert-probe/` (outside all repos).

**`src/lib/nle/headless/api.ts` (19-op JSON-RPC wire)**: **ZERO matches for "insert"** — `performInsertEdit` is class-only, **UNWIRED** (confirmed by grep; matches scout-engine row e). ## 6. VERDICT

The mode card verifies against the mock with two corrections (the down-arrow is centered on the incoming clip, not at the playhead; "multi-clip inserts land sequentially" is intent with zero implementations). The corpus runs **two insert semantics under one name**, and the spec knows it at the architecture level but not at the law level: the **placement insert** (reject-not-shift, push only via the opt-in ripple flag) is the canonical, landed algorithm — OT's ops layer, the W11 `timeline.insert` verb, the app's pool DnD, and the letter of 06 §5.9/05 §14.5/15 §4.3.9 — while the **DaVinci splice insert** (mid-clip split at the playhead + intrinsic downstream push) exists only as engine class math (`timeline.ts:4702`, unwired, correctly quarantined behind Decision 12.3's r1 port queue) and as the spec-repo's own mock implementations (`insertPlan.ts`, the mode's most faithful realization, which honestly labels itself an app-composite that "does not claim OT parity"). The mid-clip-split law — the single sentence that defines this mode — is stated in **no spec prose anywhere**; 06 10.4's "ALIGNED" row actively papers over the seam, and the one live implementation of the law carries an **unpinned, live-probed defect**: with linked clips (the default), the mid-clip insert drags the left half of the split into the inserted clip's span, violating the corpus's own global no-overlap invariant (00-master `:804`). The shipped app lands 2 of 3 insert facets (split verb + pool placement insert, non-rippling, gate-pinned); no source monitor, no `,` insert, no push. Disposition: this mode is **not spec-governed yet** — G1 (write the §5.9 law before the r1 port lands on top of a mislabeled ALIGNED row) and G2 (fix + pin the linked mid-clip path) are the two rows that must move first; G3/G4 ride the already-endorsed r1 window; the mock stays the only place the mode's full grammar (ghost, split, push, `,`) is real.
