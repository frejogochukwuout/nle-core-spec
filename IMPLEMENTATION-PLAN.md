# IMPLEMENTATION-PLAN — the executable plan (separate from the spec set)

**What this is:** THE plan — the execution runbook for the NLE project. It is deliberately NOT a numbered spec: the spec set (`00`-`20`) owns WHAT and the acceptance criteria (each spec's §0 FORWARD INVENTORY — BASE pinned / GAP with owner+acceptance / TEST PLAN, the R22 posture law); THIS doc owns HOW/WHO/WHERE — workstreams, sequencing, parallelism, entry points, gates, protocol. **There are no time estimates in this plan (D40.1): a phase ends when its exit gate is green — never on a calendar.** A gate is a command you run; a row without a machine-checkable gate is a spec bug.
**Ruling basis:** `audits/ARCH-R24-timeline-strategy-and-topology.md` (v2 — D26 the adopt-wholesale convergence / D27 the repo topology / D28 evolve-in-place + the productization gate / D29 the seam-finalization instruments; D23 plan separation + D24 the ladder stand, D25's mechanism amended per D26) + `audits/ARCH-R25-edit-mode-completeness.md` (v2 — D30 the mode-matrix law / D31 the source-edit family / D32 the linked-companion law / D33 the visual-grammar register / D34 the keyboard family / D35 the reference register / D36 the execution wiring) + **`audits/ARCH-R27-final-tightness-audit.md` (D37+ the live namespace; the R27 fleet's evidence packs: the five scouts + the six mock reports — above all `audits/fleet-r27/mock-leverage.md` the leverage map, whose Stage 0-4 order IS r1's internal sequencing) + D40 THIS overhaul (the estimates removal + the gate-defined phases + the parallel-carve law — §5 of `audits/fleet-r27/xcut-plan.md`, as amended by `audits/fleet-r27/review-plan.md` (SHIP-WITH-FIXES) + `audits/fleet-r27/review-rulings.md` (the stream arithmetic, the D38→D40 renumbering, the two count reconciliations))**. Supersedes spec 14's plan content (retired to a redirect stub; the lineage in §6).

**Stage vocabulary (D24):** **CRAWL** = the programmatic-verification layer (no human eyes; K1 module nets → K2 combined nets → K3 app-behavior nets → K4 the automated e2e exit). **WALK** = the real app wiring with humans (w1 grammar+fidelity+human rounds, w2 media, w3 project). **RUN** = the full NLE at DaVinci/web-DAW depth (r1-r6). The stages label VERIFICATION DEPTH — code lands continuously in every stream; a stage's exit gate is what sequences.
**Crawl's purpose (the user's law):** eliminate as many issues as possible before the walk — "ideally everything can continue to be tested programmatically"; human-required gates are registered below WITH reasons.
**The convergence spine (D12, ratified both sides `1064f91`):** opencut-timeline is THE editing engine (SceneTracks SSOT + the spec-15 wire); the engine's stack is the render/export venue model; the junction is one-directional (`SceneTracks → bridge → the venue stack`); engine-native edit verbs are FROZEN venue-internal — the offline reference + the parity twin that pins r1.
